# Decisions log

Short records of decisions made during the build, especially anything that differs from or fills a gap in the reference specification. Newest first. Format: **D-nnn — title** · date · status · context · decision · consequences.

- **D-018 — Suggestions S-017..S-019 accepted and scheduled** · 2026-10-06 · accepted · A\* scratch buffers at the 0.8 profiling pass (only if warranted), pawn-aware routing in Stage 1, compressed and trimmable replay logs at 0.6. Folded into Blueprint v2.3 (§7.3, §19, §20) and Roadmap v4.2.
- **D-017 — Map size cap and world schema 2** · 2026-10-06 · accepted · Maps are limited to 2048 per side and 2^21 (about 2.1 M) tiles so tile arrays stay small enough to hash and save quickly; the Blueprint gave no number. `WorldState` schema is now 2 (maps, objects, pawns tables, movement settings). Old logs and saves are not migrated (there are none in the wild yet).
- **D-016 — Replay format v2** · 2026-10-06 · accepted · Logs now store per-table hashes for every day and the final state (suggestions S-002/S-007) plus the content packs (id, version, hash) the run used; replay refuses mismatched content with a reason (the first form of S-014's compatibility report). Version 1 logs are refused, not guessed at. `pg replay --diff` and `--bisect` (S-002, S-008) are built on this.
- **D-015 — Movement rules made precise** · 2026-10-06 · accepted · Blueprint §7.4 says "the lower id moves; the other waits; sidestep to a free neighbor; after max_repaths fail". Implemented as: pawns step in ascending id order (so the lower id claims a contested tile); after `max_wait_ticks` a pawn sidesteps to the free neighbor ranked by (not straight backwards, closest to goal, N-E-S-W order) and asks for a repath; the first solve is free and each re-solve counts toward `max_repaths`; with nowhere to sidestep a pawn gives up after `max_wait_ticks * (max_repaths + 1)` with `path_blocked` so a head-on deadlock in a one-tile corridor cannot hang. Pathfinding ignores other pawns, so a pawn blocked by a stationary pawn eventually fails (`path_blocked`) rather than routing around it; smarter avoidance is a future improvement.
- **D-014 — Parallel pathfinding through a `BatchExecutor` trait** · 2026-10-06 · accepted · The core stays thread-free: it defines `BatchExecutor` and a serial implementation; `pg-runtime` supplies `ScopedThreads`. Because each path request is a pure function of (map, endpoints, edit version, cap), results are identical for any executor and thread count; this is tested (core and runtime) and checked on every OS in CI (`pg map bench-paths`). 0.8 replaces per-batch scoped threads with the long-lived worker pool behind the same trait.
- **D-013 — Suggestions scheduled and folded into the specs** · 2026-10-06 · accepted · All suggestions in `docs/SUGGESTIONS.md` were accepted and placed by priority, cost and the milestone where their prerequisite first exists (table at the top of that file). Spec copies bumped: Blueprint v2.3, Roadmap v4.2 (new principle 16, items marked [DX]), Design Document v3.1. No scope or pillar changes.
- **D-012 — Content pack rules beyond the Blueprint's wording** · 2026-10-06 · accepted · Made explicit while building 0.3: pack templates live under `data/templates/**/*.json`; only the `base` pack may define ids outside its own namespace; a template may extend only templates from its own pack or a (transitive) dependency; every inheritance chain must end at `base.object`; unknown fields are errors everywhere (templates, manifests, component params) so typos never silently do nothing. Folded into Blueprint v2.1 §4.3.
- **D-011 — Strict JSON parser, no serde for content; proptest instead of cargo-fuzz for now** · 2026-10-06 · accepted · `pg-canon::json` parses content/replay JSON and rejects floats, duplicate keys, lone surrogates and nesting deeper than 64 (serde_json silently takes the last duplicate key). Robustness is covered by proptest ("arbitrary text never panics", canonical round-trip). `cargo-fuzz` needs nightly and is deferred to Stage 11 hardening; parser and manifest fuzz targets stay on the plan.
- **D-010 — New `pg-canon` crate** · 2026-10-06 · accepted · `pg-content` needs the integer-only `Canon` value type, but `pg-core` depends on `pg-content`, so `Canon` could not stay in the core. It moved to a zero-dependency foundation crate; `pg_core::canon` re-exports it so core code is unchanged. Added to the dependency rule (`scripts/check_deps.py`) and Blueprint v2.1.
- **D-009 — `System` requires `Send`; dev probe is scaffolding** · 2026-10-06 · accepted · The sim (and its systems) will live on the dedicated sim thread (Blueprint §1), so `System: Send` is enforced from the start. `WorldState.probe` and the `dev.*` systems exist only so replay/hash/snapshot tests are meaningful before real systems exist; they are deleted (or `cfg(test)`) when Stage 1 systems land.
- **D-008 — Tick/boundary convention** · 2026-10-06 · accepted · Blueprint §6.2 says "apply inputs, advance clock, compute flags". Made precise: `step()` applies inputs stamped with the current tick `T`, advances to `T+1`, and flags describe the tick *entered* (first minute boundary at tick 10, first day boundary at 14,400; tick 0 has no flags, so world creation, not the pipeline, performs the initial day setup). `SlotMinutes` must divide 1440 so slot boundaries always align with minute and day boundaries.
- **D-007 — Hash construction for RNG** · 2026-10-06 · accepted · Blueprint §5.1 allows "xxh3-64 or splitmix64-based, implemented in-repo". Chose FNV-1a 64 (published constants) feeding the SplitMix64 finalizer, with an order-sensitive `combine`; no external crate. Validated by published FNV-1a and SplitMix64 vectors plus pinned regression vectors (`pg-core::vectors`). Changing any pinned vector changes every seeded world and needs a decision + spec bump.
- **D-006 — Canonical serialization without serde in `pg-core`** · 2026-10-06 · accepted · Blueprint pseudocode mentions `serde_json::Value`, but a hand-written `Canon` tree (sorted keys, integers only, `i128` ints, no floats representable) keeps the core free of serde and makes float-smuggling impossible by construction. serde stays in `pg-persist`/`pg-cli`, which convert at the edges.
- **D-005 — BLAKE3 `pure` feature** · 2026-10-06 · accepted · `blake3` is used with `default-features = false, features = ["std", "pure"]` so no C/asm is compiled; simplest cross-platform build, speed is irrelevant for day-boundary hashing. Revisit if hashing shows up in profiles.
- **D-003 — Edition and toolchain** · 2026-10-06 · accepted · Toolchain pinned to Rust 1.99.0 in `rust-toolchain.toml`; edition stays 2021 for now (2024 migration is optional and separate).
- **D-004 — cargo-deny deferred to 0.1** · 2026-10-06 · accepted · Plan listed it under 0.0, but with no external dependencies yet it cannot be meaningfully tested; it is added with the first dependencies in 0.1.
- **D-002 — License placeholder** · 2026-10-06 · open · Workspace license is `UNLICENSED`, `publish = false`. A license (or staying proprietary) must be chosen before any public release or before accepting outside mod/API contributions.
- **D-001 — Reference documents live in the repo** · 2026-10-06 · accepted · The three specification documents are copied to `docs/reference/` under versioned names and are the binding spec. Changes to the spec are made by editing the copies, bumping the version in the title, and adding an entry here.
