- **D-031 — Scripting spike: what 0.9 settled** · 2026-10-07 · accepted · Blueprint v2.8 §23.4, §23.6, §23.10, §23.15; details and measurements in `docs/spikes/scriptvm.md`. (1) **`mlua` with Luau stays** behind `ScriptVm`; no upgrade trigger was hit. (2) The trait differs from the sketch: the call context is data in `args` and buffered commands come back in the result (no `&mut CallCtx`), and `run_load_phase` returns `Registrations` instead of calling a `Registrar`; the VM keeps no host references and is `Send`. (3) Luau fast-calls builtins and lowers `pairs`, which bypasses removed or replaced globals: the compiler is configured with `mutable_globals` and `disabled_builtins`. String length caps are dropped because Luau's pattern matcher is interruptible. Metatables are frozen on attach. (4) Pack components apply to every entity of their kinds (defaults for unwritten fields); only written values are stored; the store is left out of the canonical form and hash while empty, so existing worlds, saves and goldens keep their hashes and the world schema stays 3. Explicit attach waits for templates (Stage 1). (5) Per-pack error history and quarantine are world state (`WorldState.ext`), so they survive snapshots, keyframes and saves; a pack that fails to load is quarantined at once. The wall-clock watchdog and `PackQuarantined` as a recorded input are deferred. (6) Scripts write only through `apply_set_field`, which validates like built-in code and lets a pack write only its own components. (7) Dependency rule: `pg-core` and `pg-content` may use `pg-api` (zero-dependency data: hook points, clamps, hints), `pg-script` may use `pg-content`, `pg-cli` may use `pg-script` and `pg-api`; the shared "did you mean" helper moved to `pg-api`. (8) Build: per-target `CXXFLAGS` in `.cargo/config.toml` turn floating-point contraction off; CI verifies with a fused-multiply-add probe and rejects `luau-jit`. (9) The first hook point is `movement.speed_modifier` (product of permille factors, clamped to 500..1500). (10) `pack.json` `entry` must name a file under `scripts/`.
- **D-030 — Choices made in 0.8** · 2026-10-07 · accepted · Blueprint v2.7 §6, §19, §20. (1) Replay format is **v4** (row-level hashes, S-023); v3 logs are refused. World schema is unchanged. (2) The long-lived worker pool runs owned (`'static`) jobs only (saves, shadow verification, later AI and worldgen); path batches borrow map data, which a persistent thread cannot hold without `unsafe`, so they keep the scoped fan-out behind the same `BatchExecutor` trait (this refines D-014's "0.8 replaces scoped threads"). (3) The profiler is a `SystemProbe` trait in the core implemented with `Instant` in `pg-runtime`, instead of the `tracing` crate, so the core stays clockless and no dependency is added; the overlay reads the same numbers. (4) Profiling result: 200 pawns on 96x72 cost 0.10 ms per tick (0.1% of the 100 ms budget at 1x, movement 70%), so A* scratch buffers (S-017) are **not** warranted now; revisit if a Stage 1 profile shows paths above 10%. (5) The GUI stack (wgpu 30, winit 0.30, egui 0.36) is added compile-only. `deny.toml` gains BSL-1.0 (Boost, permissive), an exception allowing OFL-1.1 and Ubuntu-font-1.0 for `epaint_default_fonts` only (fonts, attribution), and an ignore for RUSTSEC-2026-0192 (`ttf-parser` unmaintained, reached only through winit's Linux Wayland title bar); revisit when winit drops it. (6) Manifest summaries (S-024) are additive and optional, so older manifests still load; a thumbnail is a separate PNG blob next to the generation, cleaned up with it.

- **D-024 — Persistence design choices in 0.6** · 2026-10-07 · accepted · Blueprint v2.5 §13, §20. (1) The manifest lists both retained generations with their own hashes (the Blueprint named only the current one), so a fallback can report the time lost and verify the older file. (2) `ruzstd` provides zstd (pure Rust; D-005's no-C-build rule); only its fastest level is implemented, which is enough here, and the container records the length and a BLAKE3 checksum itself. (3) Saves hold the world at a tick boundary and exclude inputs queued for future ticks; the runtime (0.8) applies commands at the next tick so the queue is empty at a save, and the scenario runner refuses to save with a non-empty queue. (4) Imports keep entity ids and always create a new slot; the Blueprint's "id remap" is unnecessary while ids only have meaning inside one world. (5) The hardened archive reader reads `.pgpack` zip files into memory only (no extraction to disk) and enforces entry, size, total, ratio, path-safety, symlink, encryption and duplicate limits twice (central directory, then actual bytes); installation is Stage 11. (6) Replay logs gained an optional `start` state (additive; version stays 3 and untrimmed logs are byte-identical), which is also what a bug bundle is. (7) Migrations: the chain is empty (schema 3 is the first that ever existed); the framework is tested with synthetic chains and a pinned v3 fixture (`fixtures/saves/world-v3.json`).
- **D-023 — `WorldState::from_canon` and the typed `Reader`** · 2026-10-07 · accepted · Saves are decoded with a path-tracking `Reader` over `Canon` (no serde in the core, D-006). Decoding rejects unknown fields, bad ranges, table keys that disagree with row ids, and schedules that fail their own invariants, always with the path of the problem; map sizes are checked before any array is allocated. Derived fields (map edit versions, dirty chunks, occupancy, caches) are rebuilt, so equality after a round trip is by canonical form and state hash, not `==`.
- **D-022 — `Canon` key order differs from RFC 8785 for exotic keys** · 2026-10-07 · accepted · S-004's cross-check against an independent RFC 8785 serializer matched on every property-tested value except member order when keys mix U+E000-U+FFFF with supplementary-plane characters (UTF-16 order vs code point order). Engine keys are ASCII, so nothing changes; hashes stay deterministic everywhere. Left as is and pinned by a test; revisit only if canonical JSON must be verified by an external RFC 8785 tool with such keys (pack-defined keys are the only source).
- **D-021 — Scheduler, commitments and actions: choices made in 0.5** · 2026-10-06 · accepted · Blueprint v2.4 §8.5-§8.7. (1) Displacement of priority 4-5 is only reachable mid-day (`insert_urgent`), because a full plan places in priority order. (2) Replans are requested via `Pawn.replan` and done at the next slot boundary inside the ReservationActivator, so the pipeline keeps exactly 13 built-in slots and no extension systems; a failure replans from the *following* slot, which keeps the failed reservation frozen and avoids an immediate retry loop. (3) A started reservation is never displaced. (4) Gatherings use the built-in `meet_at` action with `MEET_RADIUS = 2` because two pawns cannot share a tile; attendance is judged by the same radius. (5) A slot-length change cancels live commitments and makes every schedule stale (replanned at the next boundary). (6) Performing ends on the last tick of a reservation (`end - 1`) because the activator moves the pawn on at the boundary tick, before the activity system runs. (7) A pack decision may not borrow a built-in reason sentence: only `Source::Builtin` codes use the sentence table. (8) Reservation ids are per-schedule `u32`s that survive being lifted out and replaced; `Kind::Reservation` stays reserved for a later global id if needed. Deferred to Stage 1: preconditions, permissions, costs, `Effect`s, relationship hostility in acceptance, script weight hooks.

- **D-015 — Movement rules made precise** · 2026-10-06 · accepted · Blueprint §7.4 says "the lower id moves; the other waits; sidestep to a free neighbor; after max_repaths fail". Implemented as: pawns step in ascending id order (so the lower id claims a contested tile); after `max_wait_ticks` a pawn sidesteps to the free neighbor ranked by (not straight backwards, closest to goal, N-E-S-W order) and asks for a repath; the first solve is free and each re-solve counts toward `max_repaths`; with nowhere to sidestep a pawn gives up after `max_wait_ticks * (max_repaths + 1)` with `path_blocked` so a head-on deadlock in a one-tile corridor cannot hang. Pathfinding ignores other pawns, so a pawn blocked by a stationary pawn eventually fails (`path_blocked`) rather than routing around it; smarter avoidance is a future improvement.
- **D-014 — Parallel pathfinding through a `BatchExecutor` trait** · 2026-10-06 · accepted · The core stays thread-free: it defines `BatchExecutor` and a serial implementation; `pg-runtime` supplies `ScopedThreads`. Because each path request is a pure function of (map, endpoints, edit version, cap), results are identical for any executor and thread count; this is tested (core and runtime) and checked on every OS in CI (`pg map bench-paths`). 0.8 replaces per-batch scoped threads with the long-lived worker pool behind the same trait.

- **D-008 — Tick/boundary convention** · 2026-10-06 · accepted · Blueprint §6.2 says "apply inputs, advance clock, compute flags". Made precise: `step()` applies inputs stamped with the current tick `T`, advances to `T+1`, and flags describe the tick *entered* (first minute boundary at tick 10, first day boundary at 14,400; tick 0 has no flags, so world creation, not the pipeline, performs the initial day setup). `SlotMinutes` must divide 1440 so slot boundaries always align with minute and day boundaries.
- **D-007 — Hash construction for RNG** · 2026-10-06 · accepted · Blueprint §5.1 allows "xxh3-64 or splitmix64-based, implemented in-repo". Chose FNV-1a 64 (published constants) feeding the SplitMix64 finalizer, with an order-sensitive `combine`; no external crate. Validated by published FNV-1a and SplitMix64 vectors plus pinned regression vectors (`pg-core::vectors`). Changing any pinned vector changes every seeded world and needs a decision + spec bump.
